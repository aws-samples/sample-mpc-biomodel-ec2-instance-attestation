👩‍💻 Developer Guide

Set up your local development environment and run the Boltz protein folding application

Prerequisites

Required Hardware

  • AWS EC2 Instance: Must be a Nitro-based instance type (C5n, M5n, R5n, or newer)
  • NitroTPM: Instance must have NitroTPM enabled
  • Optional GPU: NVIDIA GPU for accelerated inference (CPU mode also supported)

Required Software

Software Version Purpose
Python 3.9+ Runtime for backend and Boltz model
tpm2-tools 5.0+ TPM command-line tools
nitro-tpm-attest Latest AWS NitroTPM attestation tool
CUDA (optional) 11.8+ GPU acceleration

Environments: prod vs foa

The backend runs from an immutable, NitroTPM-attested AMI built by kiwi-ng. There is no local install path and no locally served UI. The React application is hosted on AWS Amplify and communicates with the backend through API Gateway. Two AMI build profiles exist:

ProfileUseAccess
prodProductionNo SSH, no SSM, and no cloud-init; attestable with a minimal attack surface
foaDev/TestSame AMI build plus SSH, SSM Agent, cloud-init, and debug tools; access it with aws ssm start-session

The profile is a build-time configuration held in the /boltz-attestation/build-profile SSM parameter (seeded to prod), which the CodeBuild AMI builder reads at build start. Switch the next pipeline build with no code change and no redeploy:

aws ssm put-parameter --name /boltz-attestation/build-profile --value foa --overwrite
# ... then trigger a build; set it back to prod afterwards.

For a manual/local build, pass build.sh --profile prod|foa instead.

Deploy

1. Clone and install CDK deps

git clone https://github.com/aws-samples/sample-mpc-biomodel-ec2-instance-attestation.git
cd sample-mpc-biomodel-ec2-instance-attestation/cdk
npm ci

2. Deploy the infrastructure

# Combined stack (backend + frontend + pipeline + all AWS resources)
npx cdk deploy BoltzAttestationStack --require-approval never --outputs-file cdk-outputs.json

3. Build the attested AMI and roll the ASG

cd ..
./scripts/package-and-upload.sh          # zip app/ + packaging-kiwi-ng/ -> S3 -> pipeline

4. Deploy the frontend to Amplify

./cdk/scripts/deploy-frontend.sh BoltzAttestationStack <aws-profile>

5. Access

UIThe Amplify app URL (stack output AmplifyAppUrl)
APIAPI Gateway URL (stack output ApiEndpoint); the UI is configured with this endpoint
API Docs<ApiEndpoint>/docs

Dev workflow (FOA)

For an iterate and debug loop, build the foa AMI and connect to the running instance via SSM Session Manager (no SSH keys required):

Connect to the instance

aws ssm start-session --target <instance-id> --region <region>

Inspect the backend

# Follow / read backend logs
sudo journalctl -u boltz-backend -f
sudo journalctl -u boltz-backend -n 100

# Service status + restart
sudo systemctl status boltz-backend
sudo systemctl restart boltz-backend

Deploy a code change

The AMI is immutable, so backend changes are delivered as a new AMI: edit app/backend/…, run ./scripts/package-and-upload.sh, and the pipeline rebuilds the AMI and performs a rolling update of the ASG (SSM AMI swap and instance refresh via Step Functions). Frontend changes: ./cdk/scripts/deploy-frontend.sh.

# Check TPM info
tpm2_getcap properties-fixed

Environment Variables

Variable Default Description
PORT 8000 Backend API port
MODEL_PATH / BOLTZ_CACHE /opt/boltz/models Boltz model cache dir (PCR16-measured)
CORS_ORIGINS (empty → closed) Comma-separated allowed origins. When unset the backend defaults to a closed policy (no cross-origin access) rather than *; set it to the Amplify URL.
BOLTZ_USE_MSA_SERVER false Use the remote MSA server (needs internet; off on the attested instance)
MODELS_BUCKET (unset) Optional back-compat override only; intentionally not set on the AMI. Each /models/reload request instead carries the full s3://<bucket>/… URI.
ENABLE_ATTESTATION true Enable TPM attestation
TPM_DEVICE /dev/tpmrm0 Path to TPM device
LOG_LEVEL INFO Logging verbosity
MAX_SEQUENCE_LENGTH 2048 Maximum protein sequence length

Most of these are set on the backend systemd unit baked into the AMI (packaging-kiwi-ng/overlay/etc/systemd/system/boltz-backend.service). CORS_ORIGINS is the exception: it is fetched from SSM Parameter Store at boot by boltz-config.service and written to /etc/boltz/environment, which the backend unit pulls in via EnvironmentFile=-/etc/boltz/environment (the Amplify origin is only known after the frontend deploys, and a Zero Operator Access instance cannot be edited at runtime). The accelerator (gpu/cpu) is auto-detected from torch.cuda.is_available(); no manual device flag is required.

Troubleshooting

TPM Access Denied

Error: tpm2_pcrread: Error - Failed to initialize tpm context 
# Fix: Add user to tss group and fix permissions
sudo usermod -aG tss $USER
sudo chmod 660 /dev/tpmrm0
# Log out and back in for group changes to take effect

PCR16 Still Zero

Issue: PCR16 shows all zeros in attestation 
# Check if model files exist (MODEL_PATH and BOLTZ_CACHE both point here on the AMI)
ls -la /opt/boltz/models/

# Manually verify extension
sudo tpm2_pcrextend 16:sha384=$(python3 -c "import hashlib; print(hashlib.sha384(b'test').hexdigest())")

# Restart backend
sudo systemctl restart boltz-backend

Boltz Model Not Found

Error: BoltzNotInstalledError: Boltz CLI is not installed 
# The backend runs under the system interpreter (/usr/bin/python3); there is no venv.
# Install Boltz into the system site-packages:
sudo pip3 install boltz

# For GPU support
sudo pip3 install boltz[cuda]

# Verify installation
boltz --help

Port Already in Use

# Find what's using the port
sudo lsof -i :8000

# Kill the process
sudo kill -9 PID

# Or use a different port
export PORT=8001

Detailed Code Structure

Backend Entry Point (main.py)

The FastAPI application initializes both the Boltz service and Attestation service at startup:

@app.on_event("startup")
async def startup_event():
    # Initialize Boltz model service
    app.state.boltz_service = BoltzService(...)
    
    # Initialize Attestation service (extends PCR16)
    if settings.enable_attestation:
        app.state.attestation_service = AttestationService()
        # PCR16 is extended with model hash here!

Attestation Service (attestation.py)

class AttestationService:
    def __init__(self):
        # Check TPM availability
        self._tpm_available = self._check_tpm_availability()
        
        # Extend PCR16 with model hash on startup
        self._extend_model_hash_to_pcr()
    
    def _extend_model_hash_to_pcr(self):
        # Compute SHA-384 hash of model files
        model_hash = compute_boltz_model_hash()
        
        # Extend into PCR16 (SHA-384 bank for Nitro attestation)
        tpm_extend_pcr(pcr_index=16, data_hash=model_hash)

API Routes (routes.py)

@router.get("/attestation")
async def get_attestation(req: Request, nonce: Optional[str] = None):
    # Use singleton service from app.state
    attestation_service = req.app.state.attestation_service
    
    # Generate attestation document
    attestation = attestation_service.generate_attestation(nonce=nonce)
    return attestation
